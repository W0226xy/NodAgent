# Aurora 智能仓库项目知识库测试文档

## 1. 项目概述

Aurora 智能仓库项目用于帮助中小型仓库完成入库、上架、库存盘点和异常预警。项目在 2026 年 9 月启动，试点仓库位于南京江宁区，当前仅覆盖 A 区和 B 区两个库区。

本项目的业务目标是将人工盘点误差从约 3% 降低到 0.8% 以下，并把每日盘点所需时间从 4 小时缩短到 1 小时以内。

## 2. 核心模块

### 2.1 入库登记

员工扫描货箱上的二维码后，系统记录商品编码、批次号、数量、供应商和入库时间。单次入库数量必须大于 0；若商品编码不存在，系统应提示“商品主数据未维护”，而不是自动创建新商品。

### 2.2 库位推荐

系统根据商品类别、当前库位容量和历史周转率推荐库位。易碎品优先分配到 B 区 2 至 4 层货架；冷链商品不属于 Aurora 项目第一期范围。

### 2.3 库存盘点

盘点员使用手持终端扫描货位和商品。系统将实际数量与账面数量比较：差异数量绝对值小于等于 2 时，标记为“待复核”；大于 2 时，标记为“库存异常”，并通知仓库主管。

### 2.4 异常预警

系统每天凌晨 02:00 计算异常指标。若某商品连续 3 天库存异常，或者库存周转天数超过 90 天，系统生成黄色预警；若商品缺货且存在未完成销售订单，则生成红色预警。

## 3. 技术方案

后端采用 FastAPI，数据库使用 PostgreSQL 16，缓存与异步任务使用 Redis 和 Celery。前端采用 React 与 TypeScript。系统通过 REST API 为手持终端和管理后台提供服务。

库存明细保存在 `inventory_records` 表中，关键字段包括 `product_code`、`warehouse_zone`、`location_code`、`book_quantity`、`actual_quantity` 和 `updated_at`。

## 4. 角色与权限

盘点员可以登记盘点结果，但不能直接修改账面库存。仓库主管可以审核库存异常并发起库存调整。系统管理员负责维护商品主数据、用户账号和角色权限。

## 5. 已知限制与后续计划

第一期不支持冷链仓储、跨仓调拨和自动生成采购订单。第二期计划接入 RFID 读写器，并增加按供应商维度的到货准时率分析。

## 6. 测试问答建议

上传本文档后，可在知识库中依次测试以下问题：

1. Aurora 项目的试点仓库在哪里，覆盖哪些库区？
2. 人工盘点误差和盘点时间分别要降低到什么水平？
3. 差异数量为 2 和 3 时，系统分别如何处理？
4. 哪两种情况会生成黄色预警？
5. 红色预警的触发条件是什么？
6. 冷链商品为什么不能被推荐库位？
7. `inventory_records` 表保存了哪些关键字段？
8. 盘点员、仓库主管、系统管理员的权限有什么差异？
9. 该项目第一期不支持哪些能力？
10. 第二期准备增加哪些能力？
